ChemRxiv source processing method

Process one versioned DOI at a time into source-faithful analytical characterization HTML.

Authority

The collection scope owns admission and semantic representation. The main paper and supporting information own the scientific facts and provenance; acquisition notes establish only which files were acquired or absent. Adhere to the established formats: the scope and validator define paper pages, while an existing dated index supplies the index structure. Existing paper pages are examples, not authorities. The validator does not establish scientific accuracy, completeness, or index structure.

Procedure

  1. Establish the source set

    Inventory the main paper and every acquired supporting-information source for the same versioned DOI in data/YYYY-MM-DD/. Do not mix versions or use existing HTML as a scientific source.

    File format does not determine eligibility. Each format needs a maintained inspection method that establishes exhaustive documentary coverage and preserves relevant structure. If none exists, leave the paper incomplete and stop before writing its page or index row; add format support separately. If an eligible record lacks a stable source locator accepted by the scope and validator, leave the paper incomplete and stop before writing its page or index row until that representation is supported. Do not discard a source or treat a partial conversion as complete. The local source set proves only what was acquired for this repository.

  2. Inspect every source

    Search text that exposes the scientific content and reading order reliably enough to locate analytical records, then inspect each candidate in a directly inspected source representation. For PDFs, verify candidates against rendered pages and inspect every page that cannot be searched reliably. A maintained structured-document method must inspect every documentary-bearing part, including tables, sheets, annotations, hidden parts, and embedded documents. A maintained archive method must recursively enumerate and inspect every documentary member. Never execute macros, scripts, embedded programs, or other active content. A search hit is not proof of a complete record, and a failed search is not proof that no record exists.

  3. Write the paper page

    Apply the collection scope record by record and follow the validator’s paper-page format. Name the HTML after the main-paper source stem, without its extension, and place it in ext/YYYY-MM-DD/. Read the authors, title, year, and versioned DOI from the main paper; render the title in sentence case. In the paper bibliography, link only the DOI.

    Create a negative page only after complete source coverage finds no eligible record. Review all source content, not only search hits. For a PDF, inspect every rendered page; for another format, inspect every documentary-bearing part. Use acquisition evidence and the scope’s wording to describe the supporting-information situation; local absence does not prove nonexistence.

  4. Audit the paper page

    Compare the bibliography metadata and every retained caption, identifier, label, value, qualifier, and locator with the source in a second pass. Check that no eligible record was skipped. Have a source-aware reviewer who did not transcribe the page challenge coverage, admission, transcription, ownership, and provenance; fix every substantiated defect.

  5. Update the dated index

    Follow the established dated-index format. An existing index must contain exactly one row for the paper whose link, displayed title, and analysis cells agree with the paper page. When creating an index, use an existing dated index as the structural reference and verify a one-to-one correspondence between every sibling paper page and row.

  6. Validate the change

    From the repository root, run:

    python3 scripts/validate_characterization_html.py ext/YYYY-MM-DD/MAIN-SOURCE-STEM.html ext/YYYY-MM-DD/index.html

    Fix the underlying defect behind every reported problem; do not bypass or game the validator by suppressing diagnostics, weakening required content or structure, or changing source data merely to pass. Review status and ensure the diff contains only the intended paper and index changes, with no extraction artefacts. Do not commit or publish unless requested.

Completion

Processing remains incomplete until every step above is complete and its stated proof holds.
